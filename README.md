# 萬年曆 + 奇門遁甲（拆補法）排盤

個人用的萬年曆／時家奇門遁甲**排盤**小工具，純前端、無建置流程，直接開啟 `.html` 即可使用。

## 這個倉庫只做排盤，不做解讀

2026-09-06 起，這個倉庫的範圍縮小成單一職責：**輸入生辰時間／地理經度等條件 → 算出準確的
命盤（天盤/地盤/門/星/神/值符值使/旬空等）並顯示出來**。不含任何解讀邏輯——六害判斷、格局、
用神方法、化解、白話/專業版敘事、財富七要/事業七要報告等等，全部都不在這裡。

原因：排盤（照固定演算法算出正確結果）跟解讀（怎麼判斷這個結果吉凶、怎麼用）是兩件性質完全
不同的事——前者一旦驗證正確就很穩定，後者需要長期查證累積、跨門派比對，而且是這個專案真正
花時間的地方，決定把它移到另一個私有倉庫繼續開發，這個公開倉庫只保留排盤本身。

## 檔案結構

```
index.html          萬年曆（農曆/節氣/宜忌），獨立頁面，不依賴下面任何 qimen-*.js
calendar-lexicon.js 萬年曆用的純資料表(術語百科/值神/十二建除)，index.html 用 <script src> 載入
manifest.json       萬年曆的 PWA manifest（圖示/名稱/主題色），讓瀏覽器可「加到主畫面」
icon.svg            萬年曆的 App 圖示
sw.js               萬年曆的離線快取 Service Worker，見下方「離線支援」說明
qimen.html          奇門遁甲排盤頁面（HTML 結構 + CSS）
qimen-engine.js     純排盤引擎(拆補法)，無 DOM 依賴，qimenChaibu() 是主入口
qimen-lexicon.js    九宮結構常量(GRID_ORDER/GUA_NAME/GUA_DIR/ZHI_TO_GONG)、門/星/神代號
                    對照完整名稱、起局儀軌 RITUAL_DATA——純資料，不含任何取象/吉凶內容
qimen-ui.js         唯一會讀寫 DOM 的一層：時間工具、起局按鈕(calc)、九宮格渲染(renderPan)、
                    起局歷史記錄、初始化
tests/regression.test.js   排盤引擎回歸測試(對照真實案例的快照)
```

三個 `qimen-*.js` 用傳統 `<script src>`（非 ES modules）依序載入，共用全域作用域——刻意不用
ES modules，因為本機用 `file://` 開啟時，瀏覽器的模組 CORS 限制會讓 `type="module"` 直接失效。

## 開發

```bash
npm install        # 只需裝一次 (lunar-javascript)
npm test           # 跑排盤引擎回歸測試
```

改動 `qimen-engine.js` 後，**先跑 `npm test`**，確保沒有把已驗證正確的排盤結果改壞。
`qimen-ui.js` 因為會直接操作 DOM，目前只能靠人工用 Playwright 手動驗證，還沒有留在倉庫裡的
自動化測試。

若要在瀏覽器裡本機驗證（CDN 在部分沙箱環境連不上）：起一個本機伺服器（如
`python3 -m http.server`），再攔截 `lunar-javascript`/`opencc-js` 這兩個 CDN 請求，改成餵
`node_modules/lunar-javascript/lunar.js` 的內容／回傳空字串即可，不需要真的連上 CDN。

## 排盤引擎驗證

`qimen-engine.js` 的輸出對照真實案例（荀爽老師視頻截圖逐宮核對、代碼歷史記載的邊界案例）鎖定
在 `tests/regression.test.js` 裡，涵蓋：
- 陽遁案例的天盤/地盤/門/星/神完整快照（2024-02-28 18:39）
- 陽遁「虎/玄」而非「勾/雀」的八神修正案例（1901-04-13 14:30）
- 陰遁同樣使用「虎/玄」的驗證（2024-08-01 12:00）

## 功能

- 輸入日期/時間/地點（城市快選或手動經度）→ 起局，顯示：干支、排局、值符星宮、值使門宮、
  旬首/旬空、節氣、九宮格（天盤干/地盤干/門/星/神/值符值使標記/空亡標記）
- 真太陽時校正（只做經度校正，不含均時差，留空經度則不校正）
- 起局須知／起局儀式面板（起局本身的心法/儀軌，跟盤面解讀無關）
- 起局歷史記錄（僅存本機瀏覽器 localStorage，只存輸入條件與命盤摘要，可匯出/匯入 JSON 備份）

## 已知限制

- 歷史記錄只存在單一瀏覽器的 localStorage，換裝置/清瀏覽器資料會遺失，建議定期匯出備份。
- 不含任何盤面解讀——想知道某一局代表什麼，需要另外查閱資料或使用其他工具。

## 離線支援（萬年曆）

`index.html` 會嘗試註冊 `sw.js` 做離線快取（首次連網開啟後，之後離線也能用）。瀏覽器限制
Service Worker 只能在安全來源（https 或 localhost）註冊，用 `file://` 直接開啟時註冊一定會
失敗——這是預期行為，已經用 `.catch(()=>{})` 吞掉，不影響直接開檔案的主要用法；只有部署到
真正的靜態網站（GitHub Pages 等）時離線快取才會生效。改動 `index.html` 依賴的檔案清單
（`calendar-lexicon.js`／CDN 版本號等）後，記得同步更新 `sw.js` 裡的 `CORE_ASSETS` 並升級
`CACHE_NAME`，否則使用者可能繼續吃到舊快取。
